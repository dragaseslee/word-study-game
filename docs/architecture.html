Word Study Game 架构文档

WorldWar Fourth Place Edition — Godot 4.6 综合单词学习游戏平台  |  最后更新: 2026-05-20

1. 项目概览

这是一个基于 Godot 4.6 引擎的综合单词学习游戏平台。项目设计为一个可扩展的游戏容器，通过插件式架构支持不断添加新的小游戏。目前已实现两个小游戏：「女巫的药水」和「单词配对」。

核心设计目标
  • 插件式扩展 — 新增游戏只需创建一个目录 + 注册一行代码，无需修改核心框架
  • MVVM 分离 — 视图层与逻辑层完全解耦，ViewModel 通过信号驱动 View 更新
  • 单词资源共享 — 所有游戏共享同一套单词集导入/管理系统
  • 统一导航 — SceneRouter 提供集中的场景切换和参数传递

4. 三层架构

视图层（games/*/views/、scripts/、scenes/components/）只负责 UI 渲染和用户输入，不持有游戏状态。View 通过 bind(view_model) 订阅 ViewModel 的信号。

逻辑层（games/*/view_models/、games/*_config.gd、games/*_def.gd）包含所有游戏规则和状态管理。ViewModel 通过 build_view_data() 将状态打包为 Dictionary 发送给 View。

数据层（core/autoload/word_set_store.gd、用户文件系统）管理单词集的导入、解析和缓存。

5. MVVM 模式详解

项目实现了轻量级的自定义 MVVM 框架，由三个基类组成：

5.1 ViewModel（core/mvvm/view_model.gd）

class_name ViewModel
extends RefCounted

signal view_updated(view_data: Dictionary)

func initialize(config: Dictionary = {}) -> void:
    # 一次性初始化，子类覆盖 _on_initialize()
    _on_initialize(config)
    notify_view()

func notify_view() -> void:
    view_updated.emit(build_view_data())

func build_view_data() -> Dictionary:
    # 子类必须覆盖：将当前状态打包为 Dictionary
    push_error("ViewModel subclass must override build_view_data()")
    return {}

5.2 GameView（core/mvvm/game_view.gd）

class_name GameView
extends Control

func bind(view_model: ViewModel) -> void:
    # 连接 ViewModel 的 view_updated 信号
    _view_model.view_updated.connect(_on_view_updated)

func render(_view_data: Dictionary) -> void:
    # 子类必须覆盖：根据 Dictionary 渲染 UI
    push_error("GameView subclass must override render()")

7. 游戏生命周期

每个小游戏经历三个阶段，由 SceneRouter 统一编排：

Hub
游戏选择
→
Setting
参数配置
→
Gameplay
游戏进行
→
Result
结果展示
→
Hub
返回

7.1 阶段详解

Hub（主界面）

场景：scenes/game_hub.tscn + scripts/game_hub.gd

从 GameRegistry.get_all_games() 获取已注册游戏列表，为每个游戏创建卡片。点击卡片调用 SceneRouter.goto_game_setting(game_id)。

Setting（配置阶段）

每个游戏提供自己的 Setting View + Setting ViewModel。

通用配置项：单词集选择、棋盘大小、玩家列表。

游戏特有配置：如女巫的药水的初始生命值和毒药数量。

点击"开始"时，调用 Config.build_config() 构建标准化配置字典，然后 SceneRouter.goto_gameplay(game_id, config)。

Gameplay（游戏阶段）

核心玩法阶段。ViewModel 管理所有游戏状态（棋盘、回合、得分等）。

ViewModel 通过 build_view_data() 将状态打包，View 通过 render() 更新 UI。

游戏结束时调用 SceneRouter.goto_result(game_id, results)。

Result（结果阶段）

展示排名和得分。提供「再来一局」（replay）和「返回主界面」（back_to_hub）按钮。

replay 会重新进入 Setting 阶段，使用相同配置。

7.2 参数传递机制

// SceneRouter 内部实现
var _pending_params: Dictionary = {}

func goto_gameplay(game_id: String, config: Dictionary) -> void:
    goto("gameplay_%s" % game_id, {"config": config})

func get_params() -> Dictionary:
    var params := _pending_params.duplicate(true)
    _pending_params.clear()  // 消费后清除，防止重复读取
    return params

View 在 _ready() 中调用 SceneRouter.get_params() 获取参数，然后用参数初始化 ViewModel。

游戏规则

17. 现有游戏：单词配对（word_match）

游戏规则
  • 1-10 人轮流游戏，共享一个棋盘
  • 棋盘上每个单词出现两次（一次英文、一次中文），随机排列
  • 每轮选择 2 个格子：若为同一单词的英中配对则消除，否则算一次错误

18. 如何添加新游戏

本项目采用插件式架构，添加新游戏的核心流程是：创建目录 → 实现 4 个文件 → 注册 1 行代码。下面详细介绍每个步骤。

18.1 总览：需要创建的文件

games/your_game/ ← 新游戏目录 ├── your_game_def.gd 【必须】GameDef 子类 — 游戏元信息 + VM 工厂 ├── your_game_config.gd 【必须】配置构建器 — 标准化 config 字典 ├── view_models/ │ ├── your_game_setting_vm.gd 【必须】配置阶段 ViewModel │ ├── your_game_gameplay_vm.gd 【必须】游戏阶段 ViewModel │ └── your_game_result_vm.gd 【必须】结果阶段 ViewModel └── views/ ├── setting_view.gd 【必须】配置界面脚本 ├── setting_view.tscn 【必须】配置界面场景 ├── gameplay_view.gd 【必须】游戏界面脚本 ├── gameplay_view.tscn 【必须】游戏界面场景 ├── result_view.gd 【必须】结果界面脚本 └── result_view.tscn 【必须】结果界面场景

加上修改 2 个现有文件：

  • core/autoload/game_registry.gd — 注册新游戏
  • core/autoload/scene_router.gd — 添加场景路径映射

18.2 分步指南

  1. 创建游戏目录
    在 games/ 下创建新目录，如 games/word_quiz/。目录名即为游戏标识的基础。创建子目录 view_models/ 和 views/。
  2. 实现 Config 构建器
    创建 games/word_quiz/quiz_config.gd，这是一个纯静态工具类，负责构建和验证标准化的配置字典。

    配置字典的必须字段：
    字段类型说明
    game_typeString游戏 ID，如 "word_quiz"
    word_setArray单词数组 [{en, zh}, ...]
    board_sizeint棋盘尺寸
    playersArray玩家信息数组 [{name, avatar_id}, ...]

    可添加游戏特有字段，如 rules.max_errors、initial_health 等。

  3. 实现 GameDef 子类
    创建 games/word_quiz/quiz_def.gd，继承 GameDef，设置元信息和工厂方法：

    extends GameDef

func _init() -> void:
    game_id = "word_quiz"
    display_name = "单词问答"
    display_order = 3
    icon_path = "res://asserts/buttons/button_word_quiz.png"
    setting_scene = "res://games/word_quiz/views/setting_view.tscn"
    gameplay_scene = "res://games/word_quiz/views/gameplay_view.tscn"
    result_scene = "res://games/word_quiz/views/result_view.tscn"
    bgm_stream = null

func create_setting_vm() -> ViewModel:
    return QuizSettingVM.new()

func create_gameplay_vm() -> ViewModel:
    return QuizGameplayVM.new()

func create_result_vm() -> ViewModel:
    return QuizResultVM.new()
  4. 实现三个 ViewModel
    继承 ViewModel，覆盖 _on_initialize() 和 build_view_data()：

    SettingVM — 配置阶段
    • 管理配置状态（单词集选择、棋盘大小、玩家列表、游戏特有参数）
    • 提供 start_game() 方法，调用 Config.build_config() 返回配置字典
    • build_view_data() 返回当前配置状态供 View 渲染
    GameplayVM — 游戏阶段
    • _on_initialize(config) 中根据 config 初始化游戏状态
    • 管理核心玩法逻辑（棋盘、回合、得分等）
    • 提供用户操作方法（如 select_cell()、submit_answer()）
    • 操作后调用 notify_view() 通知 View 更新
    • build_view_data() 返回完整的游戏状态
    • 游戏结束时调用 SceneRouter.goto_result()
    ResultVM — 结果阶段
    • 存储结果数据
    • 提供 replay() 和 back_to_hub() 导航方法
  5. 实现三个 View（.gd + .tscn）
    继承 GameView，覆盖 render(view_data)：

    extends GameView

func _ready() -> void:
    var params := SceneRouter.get_params()
    var vm := QuizSettingVM.new()
    vm.initialize(params.get("config", {}))
    bind(vm)

func render(view_data: Dictionary) -> void:
    // 根据 view_data 更新 UI 控件
    pass

    在 Godot 编辑器中创建 .tscn 场景文件，将脚本挂载到根节点。

  6. 注册游戏（修改 game_registry.gd）
    在 _register_builtin_games() 中添加一行：

    func _register_builtin_games() -> void:

21. 编码规范

规范说明
缩进4 空格（非 Tab）
命名snake_case 用于变量/函数/文件名，PascalCase 用于类名
语言代码注释使用中文，用户界面文字使用中文
信号信号名使用 snake_case，连接使用 signal.connect(method)
类型标注函数参数和返回值使用类型标注：func foo(x: int) -> void:
资源路径使用 res:// 前缀，不硬编码绝对路径
场景引用修改 .gd 时检查 .tscn、.tres、Autoload、输入映射是否受影响
